# Atlas application ontology 1.0.0

This is a concrete OWL application TBox for the current Atlas graph export and additive assertion profiles. Its stable vocabulary namespace is `https://w3id.org/rare-disease-atlas/vocab#`; versioned ontology identities use `https://w3id.org/rare-disease-atlas/ontology/1.0.0/`. Namespace registration and HTTP dereferencing have not been verified. These IRIs are identifiers, not a claim that a public ontology endpoint has been deployed.

## Module contract

`tbox.ttl` supplies application definitions, class separation, qualified assertion schemas, explicit source-record/identifier/aboutness relations and all native graph relation declarations. `bridge-bfo.ttl` grounds material, process, quality, role and information categories in pinned BFO 2020. `bridge-dul.ttl` separately grounds physical, event, quality, information, conceptual and institutional categories in pinned canonical DOLCE+DnS Ultralite 4.2. DUL is an OWL reengineering and extension of DOLCE; it is not the ISO DOLCE first-order specification. The old LOA-namespace DUL 3.22 download is contextual evidence only and is never substituted for canonical DUL.

The production append allowlist is exactly the manifest `deployment_modules`: application TBox and BFO bridge. The DUL bridge is a separately downloadable/queryable profile. Do not glob all Turtle files into a store. `shapes.ttl` is a validation graph, not biomedical ABox data. Full imported foundations are privately cached, checksum pinned and loaded explicitly only by validation; a production loader must not resolve moving remote imports. A reasoner using a downloaded bundle obtains the manifest source URLs, verifies SHA256 and resolves imports locally. DUL and the lecture bytes must not be redistributed until their licence is verified. BFO upstream retains CC-BY-4.0; Atlas-authored profile files use the repository MIT option. The validation result does not convert upstream licensing status into permission.

## Ontological commitments

A native released `ra:Node` denotes a projection information entry. Its indexing kind defines `DiseaseRecord`, `GeneRecord`, `PhenotypeRecord`, `PathwayRecord`, `PaperRecord`, `StudyRecord`, `GrantRecord`, `PersonRecord`, `OrganisationRecord` or `AssetRecord`. These definitions are genuine OWL equivalences to `Node AND nodeKind VALUE kind`. A canonical MONDO/HPO/HGNC IRI with only `nodeKind` metadata does not become a record because the property domain is deliberately broad. Entity records must have distinct IRIs from explicitly grounded biological referents.

`BiologicalGene` and `ProteinMolecule` are distinct material classes; `GeneRecord` is disjoint with its biological referent. Disease records, reified disease concepts, actual disease processes and disease ontology classes are different levels. Disease ontology classes remain classes in their source ontology; class-valued assertion fields are OWL punning when loaded into OWL DL, not diagnostic instances. Paper content differs from its bibliographic record; study execution differs from protocol and registration. The institutional `Organization` is not equated to `OrganizationCollective`, its current material participants. BFO `Role` and DUL's conceptual `Role` have different foundations and are not equated; the DUL profile therefore leaves Atlas realizable roles unmapped. PROV usage role vocabulary items such as `sourceInput` remain `prov:Role`, distinct from biomedical realizable role instances.

`InformationEntity` is a subclass of BFO generically dependent continuant in the BFO profile; BFO GDC is broader, so no equivalence of those categories is asserted. The three BFO defined information facets are equivalences to `InformationEntity AND GDC AND isAbout SOME GeneConcept/DiseaseConcept/PhenotypeConcept`. The DUL facets replace GDC with `dul:InformationObject`. These definitions enable interoperable joins and classification without equating a disease description with every disease concept, or BFO with DUL. `mapping-ledger.json` lists every formal equivalence/subclass bridge with its definition, evidence, confidence and review status.

Assertions are information entities. A `BiomedicalAssertion` and a `NavigationLead` are disjoint. Typing/reifying a proposition is not asserting that proposition. HOOM extraction retains frequency and diagnostic-role class references and inference guards; exclusion diagnostic roles never turn into positive phenotype evidence. GenCC classifications remain submitter/version/status scoped. Navigation, candidate identity, orthology and model relations have no transitivity, OWL identity, or treatment implication. Existing heterogeneous relations use a broad entity envelope; endpoint expectations belong to source-aware constraints, not narrow OWL domains that silently classify incomplete records.

## Change control

1. Every term needs a definition, parent commitment, source/method justification and documented application scope. Every local data/object property needs an explicit noncontradictory domain and range. Changing a predicate domain/range is a logical change, not a formatting edit.
2. Never infer individual identity from label equality, orthology, shared pathway, record identifiers, SKOS exact matching or class equivalence. Equivalence requires identical meaning or an explicit sufficient-and-necessary expression; prefer subclass or annotation when only subsumption/correspondence is supported. No blanket BFO↔DUL category equations are permitted.
3. A bridge edit includes a mapping-ledger row, upstream version/hash pin, licence/terms receipt, reasoned positive and negative fixtures, and the exact deployment module list. A bridge is reviewed separately from a source identity merge. Scientific review status remains explicit in the ledger; it must not be presented as external ontology maintainer endorsement.
4. Semver: a logical incompatibility, changed referent interpretation or removed definition increments the major ontology version; conservative new vocabulary increments the minor; annotation/typo corrections increment the patch. Keep old ontology artifacts immutable. Mark retired terms `owl:deprecated true`, add replacement/migration annotations and retain their definitions; never reuse an old IRI for a new meaning.
5. A schema release requires parser checks, checksum checks, completeness checks, OWL DL consistency and local-class satisfiability with the selected pinned foundation, SHACL positive/negative fixtures and query regression. A parsing pass is not a reasoner result. An empty/vacuous intersection, undeclared local predicate, unsatisfiable class, unintended record/material/process overlap or silent remote import blocks the schema candidate.
6. ABox migrations are separate, evidence-bearing PROV activities. Do not simply rename all gene/model/person/study nodes into material/process instances. New grounded referents require source-supported identity, their own IRIs and `represents`/`denotes`/`isAbout` links. Check old literals and class-valued endpoints against the selected profile before production inference. The present schema tests do not certify the full historical ABox.

## Reproduction and validation limits

Install `rdflib`, `owlrl`, `owlready2`, `pyshacl` and Java. Retrieve the exact manifest sources into a private cache and verify their SHA256; licence-unverified files are validation inputs only. Run:

```powershell
python scripts/build_atlas_tbox.py --cache <private-pinned-cache>
python scripts/validate_atlas_tbox.py --cache <private-pinned-cache>
```

`validation.json` records HermiT OWL DL consistency for each independently loaded full BFO/DUL profile, combined compatibility, and a deliberate gene-record/material inconsistency. Every named local base class is separately instantiated to catch unsatisfiable application classes. OWL RL fixtures verify record classification and absence of molecule/disease-process inference; SHACL rejects conflation, unknown/multiple kinds and missing assertion qualifiers. These checks concern the OWL profile, not BFO Common Logic or ISO DOLCE FOL; they do not certify a million-edge historical ABox or license its contents.
